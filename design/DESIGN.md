## 2. 指令集方案

### 2.1 为什么选 LA32R 而不是 ARM

| 对比项             | LA32R                                                                        | ARM（A32 / ARMv7）                                                                    |
| ------------------ | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 编码               | 定长；`rd[4:0]`、`rj[9:5]`、`rk[14:10]` 位置固定                             | 每条指令 `[31:28]` 都是条件码；第二操作数有旋转立即数、寄存器移位等多种形式           |
| 标志位             | **无**。6 条分支指令自带比较                                                 | 有 NZCV。`CMP` + `B<cond>` 产生标志位依赖，需额外一套冒险检测与转发                   |
| 寄存器堆端口       | 2 读 1 写足够                                                                | MLA 需 3 个读口；UMULL/SMULL 及带回写的 LDR/STR 需 2 个写口                           |
| 乘除指令           | 7 条（MUL.W / MULH.W / MULH.WU / DIV.W / DIV.WU / MOD.W / MOD.WU），均单写口 | `MUL`/`MLA`/`UMULL`/`SMULL`；**SDIV/UDIV 仅在 ARMv7VE 或 ARMv7-R 中存在**；无取余指令 |
| PC                 | 不可作通用寄存器                                                             | R15 即 PC，读出为 PC+8；写 R15 即跳转 → 任何数据处理指令都可能是分支                  |
| 与课件（MIPS）差距 | 很小，课件图可直接套用                                                       | 较大                                                                                  |
| 中文资料           | 多（龙芯杯、中科大计组实验均用 LA32R）                                       | 教学用流水线实现较少                                                                  |
| 计时器             | `RDCNTVL.W`/`RDCNTVH.W` 可读恒定频率计数器，测试程序能自测耗时               | 需自定义                                                                              |

**结论**：LA32R 在满足题目「优先考虑」要求的前提下，与课件数据通路同构，学习成本最低；ARM 的多余复杂度（条件执行、标志位、桶形移位器）基本不计分。**若将来要冲高难度，应投在微架构优化（动态分支预测、非阻塞乘除），而非换指令集。**

### 2.2 架构关键事实（已从官方手册逐条核实）

来源：《龙芯架构 32 位精简版参考手册》V1.03（[中科大镜像](https://soc.ustc.edu.cn/COD/lab1/src/LA32R_ref.pdf)），V1.04 为最新版（[阿里云镜像](https://mirrors.aliyun.com/loongson/docs/loongarch/)），实现时以 V1.04 为准。

| 事实            | 内容                                                                                                     | 影响                                                                          |
| --------------- | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 指令长度        | 全部 32 位定长，取指地址必须 4 字节对齐                                                                  | IF 级无需处理变长指令                                                         |
| 通用寄存器      | `r0`~`r31`，32 位，**r0 恒为 0**                                                                         | 写 r0 时忽略                                                                  |
| `r1`            | 标准 ABI 中为返回地址寄存器 `ra`                                                                         | `BL` 隐含写 r1                                                                |
| PC              | 不能被指令直接修改，只能被转移指令/例外间接修改；**可作为某些非转移指令的源操作数被读取**（`PCADDU12I`） | EX 级若要支持 `PCADDU12I`，需把 PC 送到 ALU                                   |
| 复位入口        | **PC = 0x1C000000**                                                                                      | 程序起始地址；上板时 IMEM 初值需与此对应，或自行在 IF 级做地址偏移（见 §3.5） |
| 标志位          | **无任何整数条件标志寄存器**                                                                             | 无需 NZCV 数据通路；条件标志寄存器只存在于浮点部分，本设计不实现浮点          |
| 分支延迟槽      | **无**                                                                                                   | 控制冒险处理比 MIPS 干净                                                      |
| 分支偏移        | 相对**该分支指令自身的 PC**：`PC = PC + SignExtend({offs16, 2'b0}, 32)`                                  | 与 MIPS 的「PC+4 为基准」不同，RTL 与汇编器都要按手册                         |
| 小数端          | 仅小尾端                                                                                                 | 访存字节序按小端实现                                                          |
| 除数为 0        | 结果**可以为任意值，且不触发任何例外**                                                                   | 硬件可自由取（如全 1、被除数、0），但必须在测试中固定并说明                   |
| 非对齐访存      | `LD.{H[U]/W}`、`ST.{B/H/W}` 地址非自然对齐将触发「地址非对齐例外（ALE）」                                | 本设计不实现例外机制，见 §3.7 的取舍说明                                      |
| `SLTUI`         | **立即数仍是符号扩展**（易错点）                                                                         | 立即数扩展逻辑不能按「无符号指令就零扩展」一刀切                              |
| `ANDI/ORI/XORI` | 立即数**零扩展**                                                                                         | 与 `ADDI.W/SLTI/SLTUI` 的符号扩展不同，需分开处理                             |
| 移位量          | 寄存器移位取 `rk[4:0]`，立即数移位为 `ui5`                                                               | 均按无符号解释，即自动 `& 0x1F`                                               |
| `MULH.WU`       | 乘积 `[63:32]` 位**符号扩展后**写入 rd（手册原文如此）                                                   | 实现时按手册写，并在测试里覆盖                                                |

### 2.3 指令清单

**实现总数：46 条基础整数指令 + NOP**（NOP 是指令 `andi r0, r0, 0` 的别名，不单列计数）。

> 口径说明：本表不含原子访存（`LL.W`/`SC.W`）、栅障（`DBAR`/`IBAR`）、系统类（`SYSCALL`/`BREAK`/`RDCNT*`）与 `PRELD`。这些指令属于特权或多核语义，与本题「流水线 CPU + 三类冒险 + 性能优化」的考察点无关，不做可避免地扩大验证面。**若时间有余，建议补 `RDCNTVL.W`/`RDCNTVH.W`——测试程序可用它自测执行周期数，是性能实验的现成手段**（见 §5）。

> 命名注意：LA32R 的计时器读指令名是 `RDCNTVL.W`/`RDCNTVH.W`/`RDCNTID`（手册 2.2.7.3），**与 LA64 的 `RDTIMEL.W`/`RDTIMEH.W` 不同**，实现与查阅资料时勿混淆；具体助记符以阶段 0 binutils 实测为准。

| 类别     | 条数   | 指令                                                                       | 格式               |
| -------- | ------ | -------------------------------------------------------------------------- | ------------------ |
| 算术运算 | 9      | `ADD.W` `SUB.W` `ADDI.W` `LU12I.W` `PCADDU12I` `SLT` `SLTU` `SLTI` `SLTUI` | 3R / 2RI12 / 2RI20 |
| 逻辑运算 | 7      | `AND` `OR` `NOR` `XOR` `ANDI` `ORI` `XORI`                                 | 3R / 2RI12         |
| 移位运算 | 6      | `SLL.W` `SRL.W` `SRA.W` `SLLI.W` `SRLI.W` `SRAI.W`                         | 3R / 2RI5          |
| 乘除运算 | **7**  | `MUL.W` `MULH.W` `MULH.WU` `DIV.W` `DIV.WU` `MOD.W` `MOD.WU`               | 3R（多周期）       |
| 访存     | 8      | `LD.B` `LD.H` `LD.W` `LD.BU` `LD.HU` `ST.B` `ST.H` `ST.W`                  | 2RI12              |
| 分支跳转 | 9      | `BEQ` `BNE` `BLT` `BGE` `BLTU` `BGEU` `B` `BL` `JIRL`                      | 2RI16 / I26        |
| 汇集     | **46** |                                                                            |                    |

对照题目「≥30 条多类指令」：**超出 16 条**，六类齐全，乘除 7 条（要求只需含乘法与除法各至少一条）。

### 2.4 编码格式

LA32R 共 9 种典型编码格式，本设计用到 6 种：

| 格式  | `[31:…]`                                               | 说明                              | 本设计用到的指令                                          |
| ----- | ------------------------------------------------------ | --------------------------------- | --------------------------------------------------------- |
| 3R    | `opcode[31:15]` `rk[14:10]` `rj[9:5]` `rd[4:0]`        | 三寄存器                          | 全部 R 型算术/逻辑/移位/乘除                              |
| 2RI5  | `opcode[31:15]` `ui5[14:10]` `rj[9:5]` `rd[4:0]`       | 5 位无符号立即数                  | `SLLI.W` `SRLI.W` `SRAI.W`                                |
| 2RI12 | `opcode[31:22]` `si12/ui12[21:10]` `rj[9:5]` `rd[4:0]` | 12 位立即数                       | `ADDI.W` `SLTI` `SLTUI` `ANDI` `ORI` `XORI` `LD.*` `ST.*` |
| 2RI16 | `opcode[31:26]` `offs16[25:10]` `rj[9:5]` `rd[4:0]`    | 16 位偏移                         | `BEQ` `BNE` `BLT` `BGE` `BLTU` `BGEU` `JIRL`              |
| 2RI20 | `opcode[31:25]` `si20[24:5]` `rd[4:0]`                 | 20 位立即数                       | `LU12I.W` `PCADDU12I`                                     |
| I26   | `opcode[31:26]` `offs[25:16][9:0]` `offs[15:0][25:10]` | 26 位偏移，**分两段存放**（见下） | `B` `BL`                                                  |

> ⚠️ **I26 偏移不是连续 `[25:0]`，而是拆成两段存**：**高 10 位在 `[9:0]`，低 16 位在 `[25:10]`**，
> 即解码式为 `offs26 = {instr[9:0], instr[25:10]}`。
>
> 实测验证（binutils 2.46.1）：`b +16` 编码为 `0x50001000`。按上式拆分解码 →
> `instr[25:10]=4`、`instr[9:0]=0` → 偏移 4 字 = 16 字节 ✓；若误按连续 `[25:0]` 解码 →
> 偏移 4096 字，跳飞。
>
> **本项目曾在此处踩坑**：单周期版 RTL 最初误写成连续 `instr[25:0]`（本行文档原先也写错），
> 导致用标准汇编器生成的 `B`/`BL` 全部跳飞；原 `test_all.hex` 是手工按错误解码构造的偏移才得以跑通。
> 详见 `DEBUG_LOG.md` 案例 2。

## 3. 微架构设计

### 3.1 总体路线：先单周期，再流水线

课程文档明确「所有学生必须至少完成一个单周期 CPU 的设计工作」，因此：

1. **先做单周期 CPU**，跑通全部 46 条指令 → 这是**中期检查**的交付物
2. **单周期版保留**，作为性能对比的基线（单周期 CPI = 1，但主频低）
3. 再改造成 5 级流水线，两份代码共用同一套 ALU / 寄存器堆 / 测试程序；**存储器按 §3.5 分别实现**（单周期用分布式 RAM、流水线用 BRAM）

这样安排的好处：单周期版能独立完成指令集的正确性验证，把「指令语义对不对」和「流水线冒险处理对不对」两类问题**分开调试**——否则两者混在一起，第一个波形就查不动。

### 3.2 单周期数据通路

直接套用课件 `doc/指令处理的数据通路/` 的经典结构（该套课件是 MIPS 版，与 LA32R 同为 Load/Store、三操作数、r0 恒为 0、分支自带比较，可直接映射）：

```
PC ──> IMEM ──> 译码 ──┬──> 寄存器堆 ──> ALU ──┬──> DMEM ──┐
                       │                       │            │
                       ├──> 立即数扩展 ────────┘            │
                       └──> 控制单元 ──────────> ALU控制     └──> 写回
                                                  │
                                      分支比较 ────┴──> 下一PC
```

与课件的主要差异（**必须注意**）：

| 差异点       | 课件（MIPS）   | LA32R                                                     | 实现影响                                                           |
| ------------ | -------------- | --------------------------------------------------------- | ------------------------------------------------------------------ |
| 分支基准     | PC+4           | **本条指令的 PC**                                         | `next_pc = pc + sext(offs16<<2)`，不能加 4                         |
| 分支指令     | 仅 `beq`       | 6 条（相等/不等/有符号小于/大于等于/无符号小于/大于等于） | 比较器需支持有符号与无符号两套                                     |
| 跳转         | `j`/`jal`/`jr` | `B`/`BL`/`JIRL`                                           | `JIRL` 目标 = `GR[rj] + sext(offs16<<2)`，与 `JR`（直接用 rs）不同 |
| 立即数扩展   | 统一符号扩展   | `ANDI/ORI/XORI` **零扩展**，`SLTUI` **仍符号扩展**        | 扩展逻辑按指令分别控制                                             |
| 大立即数装载 | `lui` + `ori`  | `LU12I.W` + `ORI`                                         | 无 `lui`，别写错                                                   |
| `PCADDU12I`  | 无             | 有                                                        | ALU 需要一个「PC」源操作数                                         |

### 3.3 五级流水线

`IF → ID → EX → MEM → WB`

| 级  | 内容                                                                                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------- |
| IF  | PC 寄存器；IMEM（BRAM）取指；`IF/ID` 寄存器（存 `pc` 与 `instr`）                                                         |
| ID  | 译码；32×32 寄存器堆（2 读 1 写，带同拍读写旁路）；立即数扩展；分支判定（若采用 ID 级方案）；控制信号生成；`ID/EX` 寄存器 |
| EX  | ALU；MDU 接口；转发 MUX；`EX/MEM` 寄存器                                                                                  |
| MEM | DMEM 访存；字节/半字对齐选择与符号/零扩展                                                                                 |
| WB  | 写回寄存器堆                                                                                                              |

### 3.4 冒险处理

#### 数据冒险（RAW）

| 情形                                                  | 处理                                                                   | 代价 |
| ----------------------------------------------------- | ---------------------------------------------------------------------- | ---- |
| EX 级指令需要前一条 ALU 指令的结果                    | EX/MEM → EX 转发                                                       | 0 拍 |
| EX 级指令需要前两条的结果                             | MEM/WB → EX 转发                                                       | 0 拍 |
| **load-use**：EX 级指令需要紧邻的前一条 `LD.*` 的结果 | 转发 + **停顿 1 拍**（冻结 PC 与 IF/ID，清空 ID/EX 控制信号为 bubble） | 1 拍 |
| `ST.*` 的存储数据需要转发                             | 该数据在 MEM 级才用，MEM/WB → MEM 转发                                 | 0 拍 |
| `MUL`/`DIV` 等 MDU 结果（多周期）                     | 由 MDU 的 `busy` 握手处理，见 §3.6                                     | N 拍 |

**转发优先级的坑（容易写错）**：当 EX/MEM 和 MEM/WB 同时命中同一寄存器时，**EX/MEM 更近，必须优先**。判断顺序写反会导致间歇性错误——只在特定指令组合下出错，最难查。

**另一个坑**：转发比较时必须排除 `rd == r0` 的情形（r0 恒为 0，写入被忽略），以及该指令根本不写寄存器（`ST.*`、分支、`NOP`）的情形。否则会转发垃圾数据。

#### 控制冒险

**基线方案（中期检查前）**：分支在 EX 级判定，静态预测「不跳转」。预测错时冲刷 `IF/ID` 与 `ID/EX`（2 条指令），代价 2 拍。

**优化方案（见 §5）**：分支判定提前到 ID 级（代价降为 1 拍），再加 IF 级的 BHT + BTB 动态预测。

> **注意**：只做 BHT（分支历史表）不做 BTB（分支目标缓冲）是无效的——BHT 只能回答「跳不跳」，预测「跳」时还需要知道「跳到哪」，而目标地址要在 ID/EX 之后才算得出来。两者必须配套，否则只能预测「不跳转」这一种结果，那本质上是静态预测。

#### 结构冒险

IMEM 与 DMEM 分离后，最经典的「取指与访存争用存储」已被设计消除。**答辩时必须能指出还剩下哪些**：

| 冲突点                     | 说明                         | 解决方案                                                       |
| -------------------------- | ---------------------------- | -------------------------------------------------------------- |
| 寄存器堆同一拍读又写       | 单端口存储无法同拍完成       | 寄存器堆内部做旁路（写穿透）：写口地址 == 读口地址时输出写数据 |
| MDU 正忙又来一条乘除       | 单套乘除硬件无法同时服务     | MDU `busy` 时阻塞 EX 级（见 §3.6）                             |
| MDU 结果与普通指令抢写回口 | 寄存器堆只有 1 个写口        | **写口仲裁**：MDU 结果优先，普通指令让位 1 拍                  |
| 分支判定需要写回结果       | EX 级判定分支时结果在 MEM/WB | 转发路径覆盖                                                   |

**最后一个（写口仲裁）是最适合拿来讲的结构冒险**——它是真实存在、有硬件代价、有波形可证的。

### 3.5 存储器实现（FPGA 特有，**最容易踩的坑**）

Artix-7 的 Block RAM 是**同步读**：本拍送地址，**下一拍**才出数据。教材里「IF 级组合逻辑直接读出指令」在 BRAM 上不成立。**单周期版与流水线版必须采用不同的存储器策略，不能共用一套**：

**单周期版（必做，中期检查交付物）——用分布式 RAM（异步读）**

单周期 CPU 要求「取指、访存、写回」在同一条指令的**同一周期**内完成。BRAM 同步读的 1 拍延迟无法满足这一要求，因此单周期版用 **LUT 实现的分布式 RAM**（异步读，组合逻辑直接出数据），写法与课件数据通路一致。4 KB 程序约占几百个 LUT（芯片 20800 个 LUT，余量充足），代价可接受。

**流水线版——用 BRAM（同步读），把输出寄存器纳入流水线时序**

流水线版才用 BRAM，且**必须把 BRAM 的输出寄存器当成流水线的一级来对待**，而不是「白捡的一级」：

```
PC 寄存器 ──> IMEM 地址口 ──(下一拍)──> IMEM 数据 = IF/ID.指令
```

**对齐要求（P0，编码前必须先画逐拍时序图）**：BRAM 输出寄存器的 1 拍延迟意味着，**送入 IMEM 的地址、流经流水线的 PC 值、指令有效位、以及 IF/ID 寄存器里的指令，四者必须严格同拍对齐**——不能出现「BRAM 输出寄存器 + IF/ID 寄存器」无意中叠加成两级延迟。DMEM 同理：`EX/MEM` 输出的地址经 BRAM 读 1 拍后，load 数据在 MEM 级末才有效，§3.4 的 load-use 停顿分析要按这个时序重新核对。

**结论**：先在纸上画好单周期版与流水线版各自的逐拍时序图，确认「指令地址、返回数据、写回目标」始终对应同一条指令，再开始写 RTL。这是本设计第一个必须做对的架构决策。

**容量规划**：

| 存储器   | 容量            | 实现                                                   | 说明                               |
| -------- | --------------- | ------------------------------------------------------ | ---------------------------------- |
| IMEM     | 4 KB（1024×32） | 流水线：1×BRAM36；**单周期：分布式 RAM（约数百 LUT）** | 仅用 1/4，余量充足                 |
| DMEM     | 8 KB（2048×32） | 流水线：2×BRAM36；**单周期：分布式 RAM**               | 含 MMIO 地址空间时不占用实际 BRAM  |
| 寄存器堆 | 32×32           | 分布式 RAM（LUTRAM）                                   | 需支持 2 读 1 写；用 BRAM 性价比低 |

芯片共 50 个 BRAM Tile、90 个 DSP，**资源余量很大，不构成瓶颈**。

**复位地址**：手册规定复位后 PC = `0x1C000000`。片上 BRAM 从 0 地址开始，因此采用以下二者之一，取其一并在报告中说明：

- **方案 A（推荐）**：IF 级直接使用 `0x1C000000` 起始，BRAM 地址取 `pc[11:2]`（忽略高位），即把 `0x1C000000` 起的地址空间映射到 BRAM 的 0 地址。
- **方案 B**：程序链接到 0 地址（`-Ttext=0`），复位后 PC 设为 0。与手册不一致，但在报告中说明「本设计为教学实现，未实现 MMU 与虚实地址翻译，PC 复位值做了简化」。

#### 3.5.1 `$readmemh` 初始化文件路径（**上板全黑的第一嫌疑**）

`imem.v` 用 `initial $readmemh(IMEM_FILE, mem)` 装载程序。这条语句有两个容易踩的坑：

1. **综合时若文件打不开，Vivado 只报 `CRITICAL WARNING`，照样生成 bit 流**。结果是一片
   **空 IMEM**（全 0 指令），上板表现为 **LED 全黑**，且不报错、不易察觉。
2. **路径解析基准是「综合运行目录」**（`cpu_single.runs/synth_1/`），**不是工程目录、也不是源文件目录**。
   而 hex 若只挂在 `sim_1` 文件集下，**不参与综合**，综合时该文件根本不在运行目录里。

**本项目的教训**：hex 放在 `sim_1/`，综合时 `$readmemh` 失败 → IMEM 全空 → 上板全黑；
而队友的 Windows 工程恰好把 hex 放对了位置 → 全亮。**同一份 RTL，两个人跑出相反结果**。

**采用的解法（已实测）**：不改文件放置、改用**综合宏传绝对路径**，与运行目录无关：

```tcl
# 在 Vivado Tcl Console 或批处理脚本中，综合前设置
set_property verilog_define [list IMEM_FILE=\"/abs/path/to/tests/hex/test_all.hex\"] [current_fileset]
reset_run synth_1
launch_runs impl_1 -to_step write_bitstream
```

**每次检查日志**：综合日志中必须有此行，否则一定是空 IMEM：

```
INFO: [Synth 8-3876] $readmem data file '...' is read successfully
```

> 另注意：**改了 hex 内容必须 `reset_run synth_1` 重跑**，Vivado 不会因 hex 变化自动重新综合。

### 3.6 乘除单元（MDU）

#### 接口与握手

```
        ┌───────────────────────────────┐
        │           mul_div_unit         │
 op[2:0] ──>  000=MUL.W  001=MULH.W  010=DIV  011=MOD   │
  is_signed ──>  有符号 / 无符号选择                    │
   a[31:0] ──>  被乘数 / 被除数                        │
   b[31:0] ──>  乘数   / 除数                          │
   start  ──>  脉冲，发起运算                          │
   ┌<── busy    高电平表示运算中（禁止再次 start）      │
   ┌<── done    脉冲，表示结果有效                      │
   ┌<── result[31:0]   MUL.W 取积低 32 位；              │
                       MULH.W/WU 取积高 32 位；          │
                       DIV.W/WU 取商；MOD.W/WU 取余数    │
        └───────────────────────────────┘
```

握手时序：`start` 与 `busy` 之间为**单周期响应**（发出 `start` 的下一拍 `busy` 必须为高）；`busy` 拉低的那一拍 `done` 与 `result` 同时有效；结果被取走后 `done` 自动拉低。

#### 时序

| 运算 | 实现                                                                       | 周期数                |
| ---- | -------------------------------------------------------------------------- | --------------------- |
| 乘法 | 利用 DSP48E1 硬核做流水线乘法器；32×32 约需 4 个 DSP（芯片有 90 个，充足） | 2~3 拍                |
| 除法 | 基 2 不恢复余数法（non-restoring），每拍 1 位                              | 32 拍 + 符号修正 2 拍 |

#### 流水线停顿策略（**题目明确要求说明，答辩必问**）

提供两档，分阶段实现：

**第一档：阻塞式（先做出来）**
EX 级检测到乘除指令时，`start` 发起运算，同时**冻结 PC 与 IF/ID、冻结 ID/EX**（乘除指令驻留在 EX 级），并向 **EX/MEM 注入 bubble**（屏蔽其后各级的控制信号），直到 `busy` 拉低。此期间整条流水线停顿。**优点**：逻辑简单、正确性易保证。**缺点**：CPI 明显变差。

**第二档：非阻塞式（性能优化项，见 §5）**
MDU 独立运行不阻塞流水线，用计分板（scoreboard）记录 MDU 的目的寄存器，当后续指令要读该寄存器时再停顿。MDU 结果与普通指令同时到达 WB 级时做**写口仲裁**。这一档同时是「结构冒险」的现成案例。

> ⚠️ **非阻塞 MDU 的 WAW 冒险**：老乘除指令的结果延迟多拍才回 WB，若其后的年轻指令先写入了**同一个**目的寄存器，老结果稍后到达会把年轻指令的正确值覆盖掉。计分板除检测 RAW（读后写）外，还必须检测 **WAW（写后写）**：后续指令与未完成的乘除指令目的寄存器相同时，须停顿该后续指令（或让 MDU 结果排队按序写回）。**只做 RAW 不做 WAW，程序会在特定指令序列下静默算错。**

#### 边界情况（必须写进测试）

| 情况         | 处理                                                                           | 依据                       |
| ------------ | ------------------------------------------------------------------------------ | -------------------------- |
| 除数为 0     | 结果可为任意值、**不触发例外**。本设计固定取「商=全 1，余数=被除数」并写入文档 | 手册 2.2.1.11              |
| `-2^31 / -1` | 商溢出。本设计固定取 `-2^31`（与常见实现一致），余数取 0                       | 需在报告中说明为自定义取舍 |
| 余数符号     | 余数与被除数同号，绝对值小于除数绝对值                                         | 手册 2.2.1.11              |

### 3.7 明确不做的东西（主动裁剪，避免无限膨胀）

| 不做项                                                    | 理由                                                                                 |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 例外与中断（`SYSCALL`/`BREAK`/ERTN、CSR、中断向量）       | 题目未要求；实现代价大（需保存/恢复状态、精确例外）                                  |

| 浮点指令                                                  | 题目要求为整数指令集                                                                 |
| 非对齐访存例外（ALE）                                     | 不实现例外机制。改用**软件约定**：测试程序保证所有访存自然对齐，报告中说明           |

### 3.8 时钟方案

板载 100 MHz 晶振 → `sys_clk_in`（P17）。**目标直接用 100 MHz，不引入 MMCM**：

- 依据：`led_blink` 在 100 MHz 约束（10 ns 周期）下 WNS = +5.75 ns，说明该器件上 100 MHz 有充裕余量
- 5 级流水线的关键路径通常是「寄存器堆读 → 转发 MUX → ALU → 分支判定 → PC」，在 Artix-7 **-1 速度等级**上通过 100 MHz 有把握，但不能保证
- **若时序不收敛**：加 MMCM 输出 50 MHz，或做流水线内部切分。**以时序报告为准**，实际可达频率也是报告里的性能数据之一

### 3.9 复位

- 使用 EGO1 的 RST 按键（原理图标号 `FPGA_RESET`，引脚 **P15**）
- ✅ **已实测确认（2026-10-15）**：该按键默认输出**高电平**、按下为低，即**低有效复位**。依据：`toolchain_check/led_blink.v` 按低有效（`sys_rst_n`）实现，上板烧录后 LED 正常二进制计数（若极性判断相反，复位将一直有效、LED 全灭不动）。**CPU 设计沿用 `sys_rst_n` 低有效约定**
- **保守做法**：RTL 内部统一采用**异步复位、同步释放**（复位输入先过两级同步器再参与逻辑），避免亚稳态；不要用纯组合的异步复位直接驱动大量寄存器

## 4. 外设接口（MMIO）

### 4.1 方案

采用**内存映射 I/O（MMIO）**：在 DMEM 地址空间中划出一段地址区间，CPU 用普通的 `LD.*`/`ST.*` 指令访问，译码逻辑把落在该区间的访问路由到外设寄存器而非 BRAM。**CPU 内部无需任何特殊指令或端口，外设对 CPU 完全透明**——这是本设计选择 MMIO 而非专用 I/O 指令的原因。

### 4.2 地址映射

| 地址          | 读写 | 内容                          | 对应外设      |
| ------------- | ---- | ----------------------------- | ------------- |
| `0xD000_0000` | W    | `led[15:0]`                   | 16 个 LED     |
| `0xD000_0004` | W    | `seg_data0[7:0]`              | 数码管 0 段选 |
| `0xD000_0008` | W    | `seg_data1[7:0]`              | 数码管 1 段选 |
| `0xD000_000C` | W    | `seg_cs[7:0]`                 | 数码管位选    |
| `0xD000_0010` | R    | `{dip_pin[7:0], sw_pin[7:0]}` | 16 位拨码开关 |
| `0xD000_0014` | R    | `btn_pin[4:0]`                | 5 个按键      |

> 地址选择理由：`0xD0000000` 在 DK 窗口范围内且远离 BRAM 地址空间，译码只需比较高 4 位，硬件代价小。

### 4.3 外设电气特性（已从 EGO1 用户手册核实）

| 外设                   | 极性                                 | 依据（用户手册 §6）                                     |
| ---------------------- | ------------------------------------ | ------------------------------------------------------- |
| LED（16 个）           | **高电平点亮**                       | §6.3「LED 在 FPGA 输出高电平时被点亮」                  |
| 按键（5 个通用 S0~S4） | **默认低电平，按下输出高电平**       | §6.1「默认为低电平，按键按下时输出高电平」              |
| 数码管                 | **共阴极**；位选与段选**均为高有效** | §6.4「FPGA 输出有效的片选信号和段选信号都应该是高电平」 |

**注意**：数码管共阴极通常意味着「段选低电平点亮」，但 EGO1 在共阴极公共极前加了三极管驱动（FPGA 提供正向信号），因此**位选（`seg_cs`）和段选（`seg_data`）都是高有效**。这一条与直觉相反，**做错会导致数码管完全不亮或全亮**，是本项目最容易浪费时间的硬件坑之一。

**段码表**（共阴、高有效，`seg_data[7:0]` 对应 `{DP,G,F,E,D,C,B,A}`）需自行推导后填入代码，并在报告中给出表格。

| `btn_pin[4:0]`                                                  | `doc/ego1.xdc.txt` 按键段         |

**约束文件注意事项**：

1. `doc/ego1.xdc.txt` 中大量使用 `//` 开头的注释。**XDC 是 Tcl 语法，注释符是 `#`**。本次验证跑通的是裁剪版 `toolchain_check/ego1_min.xdc`（全部用 `#` 注释），该官方文件尚未进过综合流程，`//` 是否被 Vivado 容忍属于未验证项。裁进 `constraints/` 前先做一次综合验证，若报错则统一替换成 `#`
2. 必须加时钟约束：`create_clock -period 10.000 -name sys_clk [get_ports sys_clk_in]`（见 `toolchain_check/ego1_min.xdc`）
3. 只保留设计实际用到的端口约束；未使用的外设端口若出现在 XDC 中会导致实现报错
4. **`constraints/` 下的每个 `.xdc` 都会被自动纳入工程并全部生效**，对同一端口重复约束会静默互相覆盖。新增约束前确认不与 `cpu.xdc` 冲突；"仅供参考"的约束不要放在这个目录

## 5. 性能优化与量化验证

> 课程文档原话：「**不能只讲概念**，需要详细讲述设计的过程，以及**如何通过实验证明**自己对改善性能所做的设计是有效的。」
> 因此**测量手段必须先于优化项设计好**——否则优化完了拿不出数据。

### 5.1 测量手段（优先做）

| 手段                       | 实现                                                                                       | 用途                                                           |
| -------------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| 硬件性能计数器             | 一组 32 位计数器：总周期数、已提交指令数、各类停顿周期数、分支预测错误次数、MDU 占用周期数 | 计算 CPI，定位瓶颈                                             |
| **拨码开关运行时切换优化** | `sw_pin[0]` 开关转发；`sw_pin[1]` 开关分支预测；`sw_pin[2]` 开关非阻塞 MDU                 | **答辩现场拨开关，数码管上的周期数当场变化**——最有说服力的演示 |
| 数码管显示                 | 8 位数码管显示「周期数」或「CPI」，或显示测试通过标志 / 出错编号                           | 上板可读的量化结果                                             |
| `RDCNTVL.W`（可选）        | 若实现该指令，测试程序可自己读计时器做软件计时                                             | 软件侧自测耗时                                                 |

### 5.2 优化项

| 优化                       | 实现要点                                          | 预期收益                               | 证明方法                                                   |
| -------------------------- | ------------------------------------------------- | -------------------------------------- | ---------------------------------------------------------- |
| **全数据转发**             | EX/MEM、MEM/WB 两级转发；`ST.*` 数据走 MEM/WB→MEM | 消除绝大多数 RAW 停顿                  | 对比「只靠停顿」版本的停顿周期数与总周期数；给出波形对比   |
| **分支判定提前到 ID 级**   | ID 级加比较器 + 到 ID 的转发路径                  | 预测错代价从 2 拍降到 1 拍             | 分支密集程序的总周期数                                     |
| **BHT + BTB 动态分支预测** | 256 项 2-bit 饱和计数器 + 分支目标缓冲            | 显著降低分支密集程序 CPI               | **预测错误率** + CPI，两者都要给                           |
| **非阻塞 MDU**             | 计分板 + 写口仲裁                                 | 乘除密集程序总周期数下降               | 乘除密集程序（矩阵乘、素数筛）总周期数；MDU 占用周期数占比 |
| **除法提前结束**           | 余数已确定时提前拉低 `busy`                       | 除法平均周期数从 32 降到 ~16           | MDU 占用周期数统计                                         |
| **单周期 vs 流水线对比**   | 两份设计都存在                                    | 用 `频率 × CPI` 换算成实际执行时间对比 | 时序报告里的可达频率 + 硬件计数器测出的 CPI                |

> ⚠️ **对照实验的实现细节**：「关闭转发」不是简单地禁用转发 MUX——那样 RAW 相关指令会直接取到旧值而算错。关闭转发的对照版本必须**同时启用完整的相关检测 + 停顿逻辑**（即退化成「纯停顿」处理器），才能得到可比的正确结果。两个版本都要跑**同一份**测试程序、输出**相同的正确结果**，只比较周期数。

### 5.3 基准测试程序（用真实负载，不用人造指令序列）

| 程序     | 测什么                         | 用到的指令        |
| -------- | ------------------------------ | ----------------- |
| 冒泡排序 | 分支密集 → 验证分支预测        | 访存、分支、比较  |
| 矩阵乘法 | 乘加密集 → 验证 MDU 与写口仲裁 | `MUL.W`、`ADD.W`  |
| 素数筛   | 除法/取余密集 → 验证除法优化   | `DIV.W`/`MOD.W`   |
| 斐波那契 | 递归/循环 → 验证 `BL`/`JIRL`   | 分支跳转、`ADD.W` |
| 汉明重量 | 移位密集                       | `SLL.W`/`SRL.W`   |

**对照实验设计**：每个程序跑「优化关闭」和「优化开启」两遍，记录总周期数，算出加速比。用拨码开关切换，同一份比特流即可完成对照——**这是本方案最有说服力的实验设计**。

### 6.1 双人协作与工程管理（重要）

**环境差异**：本机为 Fedora 44 + Vivado 2023.2，队友为 Windows + Vivado 2019.1。

**为什么 `.xpr` 不能进 git**（三层原因，均为硬性障碍）：

1. **版本单向升级**：Vivado 只能「新开旧」，不能「旧开新」。2023.2 打开并保存工程后 `.xpr` 即被升级，队友的 2019.1 **永远打不开**；反之 2019.1 建的工程，2023.2 每次打开都会强制升级，升级完他又打不开。**两台机器的工程文件根本无法互相共享**
2. **绝对路径**：`.xpr` 记录创建机器上的路径（`C:/Users/...` vs `/home/ylk/...`），跨机器即失效
3. **跨 OS 路径分隔符**：Windows `\` 与 Linux `/` 混在工程描述里，同版本也常出问题

**解法（Xilinx 官方推荐的多机协作方式）：仓库只存「源」，不存「工程」；工程用「引用式」挂源**

**源文件目录（独立于工程，新增文件也放这里）**：

| 目录                | 内容                                              | 说明                                       |
| ------------------- | ------------------------------------------------- | ------------------------------------------ |
| `rtl_single_cycle/` | 单周期 CPU 全部 10 个 .v                          | 新增 RTL 一律放这里（glob 自动纳入）       |
| `constraints/`      | `cpu.xdc`（CPU 约束）                             | 新增约束放这里（glob 自动纳入且全部生效）  |
| `sim/`              | `tb_all.v`（上板自检仿真平台）                    | 新增 tb 放这里（glob 自动纳入）            |
| `tests/asm/`        | `test_all.s`（汇编源）+ `Makefile`                | 新增测试程序放这里                         |
| `tests/hex/`        | `test_all.hex`（IMEM 初始化）                     | 由 `tests/asm/` 的 `make` 生成，勿手工编辑 |

| 进 git（可移植纯文本）                          | 不进 git（本地生成，已被 .gitignore 忽略）                                |
| ----------------------------------------------- | ------------------------------------------------------------------------- |
| `rtl_single_cycle/` 全部 .v                     | `*.xpr` 工程文件                                                          |
| `constraints/` `sim/` `tests/asm/` `tests/hex/` | `cpu_single.cache/` `cpu_single.runs/` `cpu_single.hw/` `cpu_single.sim/` |
| `design/` 文档、`doc/` 课程资料                 | `cpu_single.ip_user_files/` `cpu_single.ipdefs/`                          |
|                                                 | `*.bit` `*.jou` `*.log` `*.rpt` 等生成物                                  |

**「导入式」与「引用式」的区别（2026-10-16 已改为引用式）**：最初源码被 Vivado「导入（copy）」进 `.srcs/`，导致同一份源码存在两处、git 里的路径带工程前缀。现已迁出为独立目录，工程改为**引用（reference）**这些路径——改源文件立即生效、无两份同步问题、新增文件直接放进上述目录再 Add 即可。

**工程用脚本生成，不要手建（2026-10-16 起）**：手建容易漏掉 `IMEM_FILE` 宏（漏了就是上板全黑），故已脚本化：

```bash
# Linux
vivado -mode batch -source scripts/create_project.tcl
# Windows：双击 scripts\create_project.bat
```

脚本自动完成四件事：引用式加源、加 testbench 与 hex 到 `sim_1`、**给两个 fileset 都设 `IMEM_FILE` 宏**、指定顶层。

> 📖 **完整的构建流程、脚本清单、日常开发命令、常见问题，见 [BUILD.md](BUILD.md)。**
> 本节只保留「为什么这么组织」的设计理由，操作步骤一律以 BUILD.md 为准。

**两条构建路径并存**：工程模式（`cpu_single.xpr`，用于 GUI 仿真看波形）+ 非工程模式（`scripts/build.tcl`，纯脚本快速出 bit）。二者读同一份 `rtl_single_cycle/` 源码，产物位置不同，勿混用。

**版本兼容注意（写代码时遵守）**：

- `xc7a35t` 在 2019.1 即完整支持，器件层面无障碍
- RTL 统一用 **Verilog-2001 / 常用 SystemVerilog 子集**，避免 2019.1 不支持的过新语法；每次提交前确认写法在两边都能综合
- 约束文件语法两边通用（XDC 基于 Tcl，无版本问题）
- **仿真器差异**：若一边用 Vivado Simulator 一边用 iverilog，testbench 避免只用某一家支持的系统任务；`$readmemh`、`$display`、`$finish` 等标准任务两边通用
- **源码文件编码**：现有 .v 的中文注释是 **GBK**（Windows 侧创建），Linux 下直接看是乱码。git 按字节存储不受影响，但跨平台编辑时注意别让编辑器把整个文件转码造成全文件 diff；新写的文件统一 UTF-8，旧文件动到哪行顺手机械转码到哪行即可，不做全量转码

**git 纪律**：push 前先 `git pull --rebase`（已发生过一次网页编辑与本地提交的分叉）；`.gitignore` 已配置好，`git add` 前用 `git status` 确认没有把工程生成物带进来。**完整的分支模型、commit message 规范、提交边界、编码与冲突处理见 [GIT.md](GIT.md)**，本节只保留工程相关的协作要点。

### 8.2 参考模型（**关键手段，强烈建议做**）

用 Python 写一个逐条执行 LA32R 的**架构级模拟器**（只实现 46 条指令，约 300~500 行）：

1. RTL 仿真时，每个时钟沿输出**已提交指令**的 `(PC, 目的寄存器, 写回值)`
2. 参考模型执行同一份程序，输出同样的三元组序列
3. **逐条比对**，第一条不一致的位置就是 bug 所在

这个方法是龙芯杯选手的常用做法，把「跑完整程序看结果不对」变成「第 N 条指令就错了」——调试效率提升一个量级。测试程序越复杂，这个投入越值。

### 8.3 汇编工具链（阶段 0 必做）

**已实测跑通的流程**（见 `tests/asm/Makefile`，`make` 一键完成）：

```
test_all.s ──> as -o test_all.elf                    # 直接汇编，不加 -march/-mabi
           ──> objcopy -O binary test_all.elf test_all.bin   # 抽成纯二进制，无需 ld
           ──> od -An -tx4 -v -w4 test_all.bin > ../hex/test_all.hex  # 转 $readmemh 文本
```

> **与原计划的三点差异（实测更正）**：
>
> 1. **不需要 `ld -Ttext=0`**。IMEM 只关心指令的**相对顺序**，程序在硬件上由 `pc.v` 的复位值
>    决定起始地址（0x1C000000，§3.5 方案 A），链接地址不影响行为。直接 `objcopy -O binary` 抽 `.text` 即可。
> 2. **不需要 Python 脚本**。`od -tx4 -w4` 在 x86 小端机上按小端解释 4 字节，恰好还原出指令字面值，
>    每行一个 32 位字，就是 `$readmemh` 要的格式。
> 3. **`-march`/`-mabi` 不可用**（见 §7 警告）。

**附带收益**：`objdump -d -M no-aliases` 读出的就是官方机器码，可直接回填 §2.4 编码表——本次已据此完成访存类操作码的回填。

> 注意：`li.w` 等伪指令的**展开形式可能与其他汇编器不同**（本工具链把 `li.w $r, 0` 展开成
> `or $r,$zero,$zero`，而另一路径可能展开成 `addi.w $r,$zero,0`）。两者**语义等价、不影响正确性**，
> 意味着生成的 hex 与手工 hex **不会逐字节相同**——判据应以**行为等价（仿真 MMIO 序列一致）**为准，
> 而非机器码比对。详见 `DEBUG_LOG.md`「等价性判据」一节。
>
> `la` 等伪指令可能展开成 LA32R 中不存在的指令，编写测试程序时需避免；建议汇编后用 `objdump` 复核。

### 8.4 上板自检程序

`test_all.s` 的设计（源码在 `tests/asm/test_all.s`，252 条指令）：

1. 按 **8 个测试组**顺序执行，每组含若干测试项，每项用一组有代表性的操作数算一遍
2. 结果与**硬编码的期望值**比较（`bne 期望, 实际, FAIL`）
3. 全部通过 → **LED 全亮（0xFFFFFFFF）+ 数码管 8 位显示 "8"**（段码 0x7F），然后原地停机
4. 某项失败 → **LED 显示错误码「组号<<8 | 项号」**；数码管最低位显示**组号数字**（0~5），
   可快速定位是哪条指令错了
5. 支持源操作数为负数的用例（如 `sra.w`/`rcri.w` 用 -10 测符号扩展）

**测试组划分**：

| 组  | 覆盖指令                                                                  |

| 0   | `add.w` `sub.w` `addi.w`                                                  |

| 2   | `slt` `sltu` `slti` `sltui` `pcaddu12i`（含 PC 相对寻址自测）             |
| 3   | `and` `or` `nor` `xor` `andi` `ori` `xori`                                |
| 4   | `sll.w` `srl.w` `sra.w` `slli.w` `srai.w` `rcri.w`                        |
| 5   | `mul.w` `mulh.w` `mulh.wu` `div.w` `div.wu` `mod.w` `mod.wu`              |
| 6   | `st.w`/`ld.w`/`st.h`/`ld.h`/`ld.hu`/`st.b`/`ld.b`/`ld.bu`（验证符号扩展） |
| 7   | `beq` `bne` `blt` `bge` `bltu` `bgeu` `b` `bl` `jirl`                     |

> **未实现**：拨码开关选择「单跑某项」（原计划的第 5 条）。当前为全量跑，失败即停机显示错误码。
